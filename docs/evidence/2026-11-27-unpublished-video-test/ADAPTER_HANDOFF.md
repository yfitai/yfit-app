## Suggested future draft data record

Carry `platform`, `article_url`, `feature_key`, `body_narration`, `account_line`, `spoken_cta`, `screen_cta`, `caption_instruction`, `scene_plan`, `media_variant_key`, explicit voice binding, measured word timing and rendered-media identity as separate fields. `scene_plan` assets must match the existing live-verified library by filename/hash; crop choices must reflect actual UI and caption-safe zones.

The current local plans already carry the first ten planning fields and blocked permissions. They do **not** carry real audio, measured timing, uploaded media URLs or a functional renderer/provider binding. Their manual `claim_reviewed` flag is not automated fact checking. An approximately 20–30-second target is subject to measured speech and reading holds, not enforced by speeding narration.

Sharing a body plus six tail snippets could later reduce duplicate work, but requires an explicit composition/timing contract. The current scalar ElevenLabs/renderer chain does not already implement body-plus-tail reuse. Alternatively, generate six complete scripts using one approved voice. No cost estimate or provider equivalence is asserted here.
